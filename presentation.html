ภาพรวม

ปัญหาที่แก้ — และวิธีคิด

ก่อนมี SalesBot

  • ข้อมูลลูกค้า/สัญญากระจายใน Excel หลายไฟล์
  • ต้องเปิดไฟล์ + กรองเอง กว่าจะรู้ว่าใครใกล้หมดอายุ
  • ไม่รู้ว่า "ลูกค้าที่ฉันดูแล" มีใครบ้าง สถานะอะไร
  • ลืมตามงาน — ไม่มีที่รวมงานติดตาม

แนวคิด SalesBot

  • ถามเป็นภาษาคน — บอท query ฐานข้อมูลจริงให้ (ไม่เดา ไม่นับเอง)
  • DB เป็น source of truth — เพิ่ม/แก้ผ่านแอป ไม่กลับไปแก้ Excel
  • มีความจำ — รู้ว่าใครคือใคร, AE ไหน, เคยคุยอะไร
  • รวมงานไว้ในเว็บ — แจ้งเตือน + งานติดตาม ครบจบในที่เดียว
ความสามารถหลัก

5 ส่วนหลักของระบบ

01

Dashboard / มุมมองทีม

การ์ดสรุป (จำนวนลูกค้า, มูลค่ารวม, Active, ใกล้หมด, หมดอายุ, ยังไม่มอบหมาย) + ตารางภาพรวมตาม AE คลิกชื่อ → กรองลูกค้าของคนนั้น

02

Chat อัจฉริยะ

gpt-4o + tool-calling เรียก query จริงบน DB — อ่าน, เขียน (ลงงานติดตามจากแชท), และ จำ ผู้ใช้/ประวัติ/โน้ต

03

Data

ตารางลูกค้า (ค้นหา/กรอง/แบ่งหน้า), แท็บใกล้หมดอายุ / IR Contact, ฟอร์มเพิ่ม-แก้ + มอบหมาย AE, Export CSV, งานติดตามต่อลูกค้า

04

Notifications

รวมงานทั้งหมดในเว็บ: งานติดตาม + สัญญาใกล้หมด/หมดอายุ (คำนวณจากวันหมดอายุเทียบวันนี้), filter, ปฏิทินงาน, สรุปงานของคุณ

05

User Switcher

เลือกตัวตน (AE แต่ละคน หรือ "ทีม/Lead") มุมซ้ายล่าง — มีผลต่อ default ของแจ้งเตือน/แชท แต่ทุกคนยังดู-แก้ได้ทั้งหมด

+

Sales Radar & Self-Improve

คำนวณโอกาสขาย (retain / winback / upsell) จากข้อมูลที่มี + ระบบวิเคราะห์ปัญหาตัวเองทุกคืน (รออนุมัติก่อนใช้)

Tech Stack

Frontend

Single-Page App ไฟล์ index.html เดียว — vanilla HTML/CSS/JS ไม่มี framework

โทนเทา-ขาว เรียบหรู ไม่มี emoji ใช้ไอคอนเส้น SVG · localStorage เก็บโปรไฟล์ผู้ใช้

Backend

FastAPI 0.104 (Python 3.11) รันบน Uvicorn ที่พอร์ต 8000

เสิร์ฟทั้ง REST API และไฟล์ frontend จาก process เดียว

ฐานข้อมูล

SQLite (ไฟล์ salesbot.db) เป็น default — เบา ไม่ต้องตั้ง server

ผ่าน SQLAlchemy 2.0 ORM → สลับเป็น PostgreSQL ได้ทันทีด้วย DATABASE_URL

AI / LLM

OpenAI gpt-4o (SDK 2.41) ผ่าน function / tool-calling

โมเดลเลือกเรียก "เครื่องมือ" → backend ไป query DB จริง → ตอบจากข้อมูลจริง

Data Import

openpyxl อ่าน Excel 2 ไฟล์ (สัญญา + ผู้ติดต่อ IR) → seed ลง DB

idempotent (upsert) — รันซ้ำได้เมื่ออัปเดตไฟล์ต้นทาง

Notifications

SMTP — Microsoft 365 / Outlook สำหรับส่งสรุปทางอีเมล (ออปชัน)

ถ้าไม่ตั้งค่า → คืนพรีวิวจำนวนรายการแทน ไม่ error

แชท 1 คำถามทำงานยังไง

  • 1. ผู้ใช้พิมพ์ → frontend ส่ง POST /api/chat พร้อม memory ของผู้ใช้
  • 2. backend แนบ นิยาม tools + ประวัติ ส่งให้ gpt-4o
  • 3. โมเดลตัดสินใจเรียก tool (เช่น search_customers)
  • 4. backend รัน query จริงบน DB → คืนผลให้โมเดล
  • 5. โมเดลสรุปเป็นคำตอบภาษาคน (วน loop ได้หลาย tool)
  • 6. เก็บความจำ (chat history, โน้ต, ข้อเท็จจริงลูกค้า) ลง DB

ความจำ · ทำไมบอทตอบ "ลูกค้าที่ฉันดูแล" ได้

3 ชั้นของความจำ

PROFILE

จำว่าผู้ใช้คือใคร — อีเมลจริงจาก login + เป็น AE คนไหน + บทบาท → คำถามคลุมเครือตอบเฉพาะของคนนั้น

CHAT (rolling)

จำบทสนทนาล่าสุดต่อเนื่อง → ถามต่อเนื่องได้โดยไม่ต้องเท้าความใหม่

CUSTOM

พูดว่า "จำไว้นะ ..." → เก็บโน้ตส่วนตัวของผู้ใช้

Customer Memory — ความจำของทีม (institutional)

AI ดึงข้อเท็จจริงจากแชทมาบันทึกต่อลูกค้าแต่ละราย (หรือผู้ใช้เพิ่มเอง) → รอบหน้าใครถามถึงลูกค้ารายนี้ บอทดึงความจำมาเสริมได้ทันที — ความรู้ไม่หายไปกับคนใดคนหนึ่ง

Winback — ดึงกลับ

ลูกค้าซื้อ IR อย่างเดียว เรียงตามเกรด+มูลค่า → เสนอ WD เพิ่ม

  • Stack เบา deploy ง่าย — FastAPI + SQLite ใน Docker container เดียว

  • พร้อมโต — สลับ Postgres ได้ด้วยตัวแปรเดียว
  • มีความจำระดับทีม + ระบบพัฒนาตัวเองแบบมีมนุษย์อนุมัติ

  • ถามภาษาคน ได้คำตอบทันที — ไม่ต้องเปิด Excel
  • เห็นภาพรวมทีม + งานของตัวเอง ครบในเว็บ
